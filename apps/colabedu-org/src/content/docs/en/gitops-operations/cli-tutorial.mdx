# ColabEdu CLI Reference

The `ce-svc-cli` is the command-line interface for operating the ColabEdu pedagogical curation pipeline. Commands are organized into nine functional groups:

| Group | Prefix | Description |
|---|---|---|
| **Curator** | `curator` | AI curation, Bloom derivation, E2E tests, and batch generation |
| **Document Discovery** | `docs` | Document discovery, download, and cataloging |
| **Taxonomy** | `taxonomy` | Standards, rubrics, and course exploration |
| **Spec Batch** | `spec batch` | Declarative, staged pipeline |
| **Curriculum** | `curriculum` | Gap analysis, ACA plan creation, progress tracking, and course provisioning |
| **LMS** | `lms` | E2E LMS provisioning, teardown, and bridge registration |
| **User Operations** | `user` | User provisioning |
| **Grading** | `grading` | Headless correction pipeline (Grading V2) |
| **CRM Operations** | `crm` | Lead import from CSV |

## Environment Configuration & Multi-Tenant Connectivity

The `ce-cli.sh` CLI allows you to operate seamlessly against multiple Kubernetes clusters, isolated on-premise VMs (BYO-VM), managed Cloud environments, and demonstration tenants running in separate namespaces, automatically resolving endpoints and authentication tokens.

### 1. Global Environment Variables

```bash
# Core Connectivity
export COLABEDU_API_BASE_URL=http://localhost:8081     # Core Platform Backend URL
export CURATOR_API_BASE_URL=http://localhost:8081     # AI Services / Curator Backend URL
export CE_SPECS_ROOT=/path/to/ce-specs               # Specs repository root

# Authentication & Credentials
export COLABEDU_AUTH_TOKEN="Bearer <jwt>"             # Manual JWT Bearer token
export COLABEDU_DEV_ROLE=ADMIN                        # Zero-friction Dev-Bypass (ADMIN, TEACHER, STUDENT)
export COLABEDU_INTERNAL_API_KEY=<key>                # X-Internal-API-Key

# Optional (external source discovery)
export COLABEDU_API_KEY_CANVAS=<token>               # Canvas Commons API
export COLABEDU_API_KEY_EUROPEANA=<wskey>            # Europeana Education API
export GOOGLE_CSE_API_KEY=<key>                      # Google Custom Search API
export GOOGLE_CSE_ID=<cx>                            # Google CSE ID
```

### 2. Global Dynamic Target Flags

Instead of modifying environment variables for each invocation, you can supply dynamic target flags to `./ce-cli.sh`:

```bash
# Connect to a specific demo tenant (resolves to https://api.<client>.demo.colabedu.net)
./ce-cli.sh --env=demo-oxford curator curate --batch

# Connect to autonomous MicroK8s catalog factory cluster
./ce-cli.sh --env=catalogo auth status
./ce-cli.sh --env=catalogo spec batch run --batch=ce-specs/batches/batch_01_ap_slc_frq_2023.yaml

# Connect to an on-premise VM by IP (port 8080)
./ce-cli.sh --env=vm:10.142.227.238 auth status

# Connect to an arbitrary backend URL
./ce-cli.sh --url=https://api.myinstitution.edu auth status

# Impersonate teacher role without interactive login (Dev-Bypass)
./ce-cli.sh --env=demo-oxford --role=TEACHER oer discover --subject="Spanish"
```

### 3. Authentication with Sovereign Keycloak

For enterprise environments and VMs requiring Keycloak JWT credentials:

```bash
# Login and exchange credentials for a token saved in ~/.config/colabedu/auth.json
./ce-cli.sh auth login https://api.oxford.demo.colabedu.net admin SuperSecretPassword colabedu

# Inspect active connection target, identity mode, and resolved role
./ce-cli.sh auth status

# Terminate session
./ce-cli.sh auth logout
```

<Aside type="caution">
The corresponding backend (`ce-svc-parent` or `ce-svc-ai-services`) must be reachable at the resolved URL before executing commands that access the API.
</Aside>

## Group `curator` — AI Curation Pipeline

### `curator curate`

Launches the AI curation pipeline on a local file or GCS URI and downloads the generated YAMLs.

```bash
curator curate --source <file-or-gs-uri> --referenceCode <code>
               [--sections "A,B"] [--type C2_EXERCISES]
               [--output <dir>] [--country <cc>]
               [--standard <std>] [--level <level>] [--subject <slug>]
               [--source-type WEB|LMS_PACKAGE]
               [--output-type RECIPE|INTERACTIVE_LESSON|RESOURCE_LEARNING]
               [--sandbox true|false] [--validate true|false]
               [--user <email>]
```

**Flags:**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--source` | `String` | **required** | Local path (PDF, DOCX, `.imscc`, `.mbz`) or GCS URI (`gs://...`) |
| `--referenceCode` | `String` | — | Taxonomic reference code (e.g. `es.lomloe.bach.2.lcl`). Auto-resolves standard, level, and subject. |
| `--sections` | `String` | — | Comma-separated section names: `"Section I,Section II"` |
| `--type` | `String` | `C2_EXERCISES` | Spec type to generate |
| `--output` | `String` | `./curator_out` | Output directory for YAMLs |
| `--country` | `String` | *(from referenceCode)* | Country code override |
| `--standard` | `String` | — | Curriculum standard override (e.g. `LOMLOE`, `IB`). Ignored when `--referenceCode` is used. |
| `--level` | `String` | — | Education level override (e.g. `4 ESO`, `2 BACH`). Ignored when `--referenceCode` is used. |
| `--subject` | `String` | — | Subject override (e.g. `lcl`, `matematicas`). Ignored when `--referenceCode` is used. |
| `--source-type` | `String` | *(auto)* | `WEB` or `LMS_PACKAGE`. Auto-detected: `.imscc`/`.mbz`/`.zip` → `LMS_PACKAGE`. |
| `--output-type` | `String` | `RECIPE` | `RECIPE` \| `INTERACTIVE_LESSON` \| `RESOURCE_LEARNING` |
| `--sandbox` | `boolean` | `true` | Write YAMLs to disk without registering in DB |
| `--validate` | `boolean` | `true` | Structurally validate downloaded YAMLs |
| `--user` | `String` | — | Email of the user who will own the job. Without this flag, the job is created as **shared** (`shared=true`) and visible to all pedagogues with `CONTENT_CREATOR`, `TEACHER`, or `ADMIN` role. |
| `--visibility` | `String` | `PUBLIC` | Visibility of the ingested spec: `PUBLIC` (available to all users) or `PRIVATE` (seed only — not served to students, used as derivation source for Bloom). |

**Internal flow:**

```
curator curate
    │
    ├─ 1. POST /api/v1/curator/curate  → workflowId
    │       (body: headless=true, sandboxMode, specType, referenceCode,
    │              rawContentBase64 / storageUrl, lmsSourceType, outputType)
    │
    ├─ 2. Poll GET /api/v1/curator/status/{workflowId}
    │       every 3s, timeout: 300s
    │       states: RUNNING → COMPLETED | FAILED | ERROR
    │
    ├─ 3. Download proposedSpecs[] → {workflowId}_spec_{n}_{outputType}_{ts}.yaml
    │
    └─ 4. (optional) curator validate on each downloaded file
```

**Examples:**

### `curator validate`

Structurally validates a curator-generated YAML spec.

```bash
curator validate --spec <path-to-yaml>
```

| Flag | Description |
|---|---|
| `--spec` | **Required.** Path to the YAML file to validate. |

Checks that the YAML has `metadata` block (with `type` and `id`) and `spec` block (with `exercises[].prompt` if applicable).

**Example:**
```bash

```

### `curator test`

Runs E2E test cases from the test manifest and generates a Markdown report.

```bash
curator test [--case <id>] [--all] [--manifest <path>] [--report true|false]
             [--output <dir>] [--lms]
```

| Flag | Default | Description |
|---|---|---|
| `--case` | — | Run a single test case by ID |
| `--all` | `false` | Run all test cases in the manifest |
| `--manifest` | `ce-specs/tests/curator_test_manifest.yaml` | Path to YAML manifest |
| `--report` | `true` | Generate Markdown report in output directory |
| `--output` | `./curator_out` | Output directory (creates `yyyy-MM-dd/` subdirectory) |
| `--lms` | `false` | Use `lms_curator_test_manifest.yaml` instead of default |

<Aside type="tip">
Use `--lms` to run LMS (Canvas/Moodle) and OER resource test cases. The manifest is located at `ce-specs/tests/lms_curator_test_manifest.yaml`.
</Aside>

**Examples:**
```bash
# Single case from classic manifest
curator test --case ap_spanish_2023_ordinaria

# All LMS/OER cases
curator test --lms --all

# Custom manifest
curator test --manifest my-tests/batch_test.yaml --all --output ./results

# Without Markdown report
curator test --all --report false
```

### `curator bloom derive`

Derives new pedagogical exercises from an ingested seed spec using a configurable Bloom strategy.

```bash
curator bloom derive --seed <referenceCode>
                     [--strategy SOURCE_DERIVATION|PROGRESSION|MISCONCEPTION_REMEDIATION]
                     [--context <standard/level/subject>]
                     [--levels SIMPLIFIED,STANDARD,EXTENDED,CHALLENGE]
                     [--count <n>]
                     [--focus <topic>]
                     [--output <dir>]
                     [--sandbox]
```

**Flags:**

| Flag | Default | Description |
|---|---|---|
| `--seed` | **required** | `referenceCode` of the ingested seed spec |
| `--strategy` | `SOURCE_DERIVATION` | Bloom strategy to apply |
| `--context` | *(from seed)* | Curricular context: `IB/HL/spanish_language` |
| `--levels` | *(all 4)* | Difficulty tiers (PROGRESSION only): `SIMPLIFIED,STANDARD,EXTENDED,CHALLENGE` |
| `--count` | `2` | Number of exercises to generate (ignored for PROGRESSION) |
| `--focus` | — | Topic or section to focus on within the seed |
| `--output` | `./bloom_out` | Output directory for generated YAML specs |
| `--sandbox` | `false` | Generate YAML files locally without registering in SpecManager |

**Endpoint:** `POST /api/v1/bloom/derive`

**Bloom Strategies:**

| Strategy | Description | Best for |
|---|---|---|
| `SOURCE_DERIVATION` | **Default.** Uses seed as L1 inspiration; generates L2–L6 as independent exercises. Copyright-safe. | Mass-scale derivation from exam PDFs |
| `PROGRESSION` | Each difficulty tier builds on the previous. Generates SIMPLIFIED → STANDARD → EXTENDED → CHALLENGE. | Adaptive learning paths |
| `MEMORY_BLOOM` | Only L1–L2 (recall + comprehension). Fast and lightweight. | Short seeds, vocabulary exercises |
| `APPLICATION_BLOOM` | L3–L4 (application + analysis). Practice-focused. | Mid-level skills |
| `ANALYSIS_BLOOM` | L4–L6 (analysis + synthesis + evaluation). Critical thinking. | Advanced / IB-style exercises |

**Examples:**

<Tabs>
<TabItem label="Source Derivation">
```bash
# Derive 3 exercises from a private source document
curator bloom derive \
  --seed ib.spa.textual_analysis_rubric \
  --strategy SOURCE_DERIVATION \
  --context IB/HL/spanish_language \
  --count 3
# → Generated: bloom_out/ib.spa.derived.ex_001.yaml
#              bloom_out/ib.spa.derived.ex_002.yaml
#              bloom_out/ib.spa.derived.ex_003.yaml
# → Each YAML has metadata.provenance.seedRef = ib.spa.textual_analysis_rubric
```
</TabItem>
<TabItem label="Progression (Difficulty Tiers)">
```bash
# Generate all 4 difficulty variants from an existing exercise
curator bloom derive \
  --seed ib.spa.textual_analysis_ex_001 \
  --strategy PROGRESSION
# → Generated: *_SIMPLIFIED.yaml, *_STANDARD.yaml, *_EXTENDED.yaml, *_CHALLENGE.yaml

# Only generate two tiers
curator bloom derive \
  --seed ib.spa.textual_analysis_ex_001 \
  --strategy PROGRESSION \
  --levels SIMPLIFIED,CHALLENGE
```
</TabItem>
<TabItem label="Memory Bloom">
```bash
# Quick L1-L2 derivation for vocabulary seeds
curator bloom derive \
  --seed global.ib.spanish_b.vocab.unit3 \
  --strategy MEMORY_BLOOM \
  --count 5
# → 5 recall/comprehension exercises, fast generation
```
</TabItem>
<TabItem label="Sandbox Preview">
```bash

  --seed ib.spa.lomloe_rubric_2025 \
  --strategy SOURCE_DERIVATION \

  --sandbox
```

## Group `docs` — Document Discovery

### `docs discover`

Discovers exam documents from known sources or web search.

```bash
docs discover [--query "<text>"] [--source <id>] [--subject <slug>]
              [--years "2022-2024"|"2022,2023"] [--call-type ordinaria|frq|mcq]
              [--output <file.yaml>] [--dry-run]
```

| Flag | Description |
|---|---|
| `--query` | Free-text for web search (requires Google CSE configured) |
| `--source` | Known source ID: `collegeboard`, `madrid`, `boe`, `canvas-commons`, `ck12`, `europeana`... |
| `--subject` | Subject slug: `lcl`, `matematicas`, `spanish_language`, `biology`... |
| `--years` | Range `"2022-2024"` or list `"2022,2023"` |
| `--call-type` | `ordinaria` \| `extraordinaria` \| `frq` \| `mcq` |
| `--output` | Saves discovery list to a YAML file |
| `--dry-run` | List candidates without HTTP verification |

**Internal strategies:**

```
docs discover
    │
    ├─ [--source canvas-commons|ck12|europeana] → LmsPackageDiscoveryStrategy (API)
    │
    ├─ [--source collegeboard|madrid|boe...]     → KnownSourcesStrategy (HEAD check URLs)
    │
    └─ [--query "..."]                           → WebSearchStrategy (Google CSE)
```

**Examples:**
```bash
# AP College Board exams
docs discover --source collegeboard --subject spanish_language --years 2020-2024 \
  --output ap_spanish.yaml

# Spanish selectividad (Madrid)
docs discover --source madrid --subject lcl --years 2022-2024 \
  --call-type ordinaria --output selectividad_lcl.yaml

# Free web search (requires Google CSE)
docs discover --query "AP Spanish Language and Culture 2023 exam" --output web_ap.yaml

# Canvas Commons packages (requires COLABEDU_API_KEY_CANVAS)
docs discover --source canvas-commons --subject biology --output canvas_bio.yaml

# Europeana resources (requires COLABEDU_API_KEY_EUROPEANA)
docs discover --source europeana --subject history --output europeana_history.yaml

# Dry-run to explore without downloading
docs discover --source boe --subject matematicas --years 2023 --dry-run
```

### `oer discover` — Federated OER Discovery & Planetary Forensic Audit

Executes semantic planetary discovery and multi-criteria quality certification (4 vectors) across the federated network of open educational repositories (>65 sovereign repositories across 52 countries). Supports forensic audit export as Markdown tables with direct resource URLs, disk file output, or structured JSON.

```bash
./ce-cli.sh oer discover --subject=<subject> [--framework=<framework>] [--format=summary|table|md|json] [--output=<file>]
```

| Flag | Default | Description |
|---|---|---|
| `--subject` | (required) | Subject or pedagogical concept to discover (e.g. `GEOMETRY_PYTHAGORAS`, `SPANISH_LANGUAGE_ARTS`) |
| `--framework` | `GLOBAL` | Territorial normative framework (e.g. `standard.lomloe.es`, `College Board AP CED`, or `GLOBAL` for ecumenical search) |
| `--format` | `summary` | Output format: `summary` (CLI summary), `table` / `md` (Markdown table with web links), `json` (raw JSON) |
| `--output`, `-o` | (stdout) | Disk path where the audit report will be directly written (e.g. `ce-docs/reports/report.md`) |

**Examples:**
```bash
# Global search for the Pythagorean Theorem with hyperlinked Markdown table output
./ce-cli.sh oer discover --subject="GEOMETRY_PYTHAGORAS" --framework="GLOBAL" --format=md

# Direct export to documentation file
./ce-cli.sh oer discover --subject="GEOMETRY_PYTHAGORAS" --framework="GLOBAL" --format=md --output=ce-docs/reports/pythagoras_audit.md
```

### `oer batch-transform` — OER Batch Harvester Factory & Transformation Queue

Orchestrates unattended batch transformation of OER packages and media (`.elp`, `.mbz`, `.imscc`, `.h5p`, `.epub`, `.html`, `.pdf`) into interactive A2UI lessons and OPS v0.9.6 specifications.

- **Zero-Cost Idempotency**: Performs pre-flight SHA-256 hash checks against database (`spec_definitions.source_file_hash`); existing items are skipped immediately with $0.00 inference cost.
- **Domain Politeness Delay**: Enforces respectful spacing between consecutive requests to the same institutional repository domain to avoid IP bans.
- **Adaptive LLM Rate Limiting**: Regulates Vertex AI / Gemini Flash quota using a Token Bucket (RPM and TPM) with exponential backoff and randomized jitter on HTTP 429 (`RESOURCE_EXHAUSTED`).

```bash
./ce-cli.sh oer batch-transform --manifest=<path> [--concurrency=<N>] [--dry-run]
```

| Flag | Default | Description |
|---|---|---|
| `--manifest`, `-m` | (required) | Path to the curated YAML batch manifest (`OerBatchManifest`) |
| `--concurrency` | `4` | Number of concurrent worker threads for downloading and processing |
| `--dry-run` | `false` | Verifies manifest, URL connectivity, and SHA-256 hashes without calling LLMs or persisting specs |

**Examples:**
```bash
# Pre-flight check in Dry-Run mode without token consumption
./ce-cli.sh oer batch-transform --manifest=ce-specs/batches/samples/oer_sample_batch_es_sciences.yaml --dry-run

# Run full parallel batch transformation with 4 workers
./ce-cli.sh oer batch-transform --manifest=ce-specs/batches/samples/oer_sample_batch_es_sciences.yaml --concurrency=4
```

## Integrated Workflow: Seed & Bloom + Curriculum Lifecycle

This is the full end-to-end workflow for onboarding a new curriculum standard from scratch:

<Steps>
1. **Analyze gaps** — Understand what's missing before starting any batch.

   ```bash
   curriculum gaps --standard IB --country global
   # → Identify: Paper 2 Writing (HL+SL) has 12-spec deficit
   ```

2. **Discover & fetch sources** — Find official exam documents.

   ```bash
   docs discover --source ibdocs --subject spanish_b --years 2019-2024 \
     --output ib_sb_sources.yaml
   docs download --list ib_sb_sources.yaml --local-dir ce-specs/sources/ib/spanish_b/
   ```

3. **Ingest seeds** — Curate PDFs into private BLOCK_CONTENT specs (F3).

   ```bash
   # Using batch YAML for production runs
   spec batch run ce-specs/batches/batch_25_ib_spanish_b_seeds_paper2.yaml
   # Or individually:
   curator curate \
     --source ce-specs/sources/ib/spanish_b/ib_paper2_hl_nov2023.pdf \
     --referenceCode global.ib.spanish_b.paper2.hl.nov2023 \
     --visibility PRIVATE
   ```

4. **Expand with Bloom** — Derive L2–L6 exercises from each seed (F4).

   ```bash
   spec batch run ce-specs/batches/batch_26_ib_spanish_b_bloom_expand.yaml
   # Or for a single seed:
   curator bloom derive \
     --seed global.ib.spanish_b.paper2.hl.nov2023 \
     --strategy SOURCE_DERIVATION \
     --count 5
   ```

5. **Assemble bundles** — Group seeds + derivations into course units (F5).

   ```bash
   spec batch run ce-specs/batches/batch_27_ib_spanish_b_assemble_bundles.yaml
   # Or:
   curriculum bundle assemble --standard IB --level HL --strategy SEED_AND_BLOOM
   ```

6. **Publish pathways** — Materialize as Teacher Dashboard entries (F6).

   ```bash
   spec batch run ce-specs/batches/batch_28_ib_spanish_b_assemble_pathways.yaml
   ```

7. **Verify coverage** — Check the sprint improved the curriculum.

   ```bash
   curriculum progress --standard IB --country global
   # Paper 2 Writing: 93% (14/15 specs) ✅
   ```

8. **Provision course** — Create live course for a teacher (F7).

   ```bash
   curriculum catalog list   # find the bundle ref
   curriculum course provision \
     --bundle-ref global.ib.spanish_b.paper2.hl.bundle.v1 \
     --org-id 5 --teacher-id 42
   ```

9. **Connect to LMS** — Register LTI bridge for Canvas/Moodle delivery.

   ```bash
   lms provision --file lms-ib-spanish-b.yaml --suffix ib-sprint-01
   lms register-link \
     --classroom-id <colabedu_classroom_id> \
     --spec-ref global.ib.spanish_b.paper2.hl.bundle.v1 \
     --lms-platform canvas \
     --lms-assignment-id <canvas_assignment_id>
   ```
</Steps>

### `lms provision`

Provisions a complete LMS environment (organizations → courses → users → assignments) from a YAML template on every configured platform.

All created resources are named with `<suffix>` to enable safe selective teardown.

```bash
lms provision --file <yaml> --suffix <suffix> [--dry-run] [--canvas-only] [--moodle-only]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--file` | **required** | Path to YAML fixture template (supports `{{suffix}}` tokens) |
| `--suffix` | **required** | Run-specific suffix appended to all resource names (e.g. `lms-test-20260622`) |
| `--dry-run` | `false` | Validates YAML and prints plan without executing any remote calls |
| `--canvas-only` | `false` | Skip Moodle, only provision Canvas |
| `--moodle-only` | `false` | Skip Canvas, only provision Moodle |

**Endpoint:** `POST /ops/v1/lms/provision-lms-from-yaml`  
**Timeout:** 180 s (Canvas/Moodle calls are remote — generous read timeout applied automatically)

**Example YAML template** (`lms-ib-spanish-b.yaml`):
```yaml
organizations:
  - name: "Test School {{suffix}}"
    courses:
      - name: "IB Spanish B HL {{suffix}}"
        courseCode: "IB-SPA-B-HL-{{suffix}}"
        users:
          - email: teacher@test.com
            role: teacher
          - email: student1@test.com
            role: student
        assignments:
          - name: "Paper 2 Writing HL {{suffix}}"
            points: 20
```

**Example:**
```bash
lms provision \
  --file ce-specs/e2e/lms-ib-spanish-b.yaml \
  --suffix ib-sprint-01

# 🏗️  LMS Provision — suffix=ib-sprint-01
# ══════════════════════════════════════════════
#   Courses created:     2
#     ✅ [canvas] id=678  IB Spanish B HL ib-sprint-01
#     ✅ [moodle] id=42   IB Spanish B HL ib-sprint-01
#   Users enrolled:      4
#   Assignments created: 4
#     📝 [canvas] id=456  Paper 2 Writing HL ib-sprint-01
#
#   ✅ Done — suffix=ib-sprint-01
```

Selectively deletes LMS courses whose names contain the supplied `suffix`.

### `course bootstrap-all` (7-Phase DAG Pipeline with Fail-Fast & Idempotent Resumption)

`./ce-cli.sh course bootstrap-all` orchestrates complete course onboarding through a strict 7-phase Directed Acyclic Graph (DAG) with forensic verification gates (*anti-404 gatekeeper*):

1. **Phase 1: Normative Grounding & C0 Taxonomy**: Competency synthesis and canonical misconceptions catalog verification.
2. **Phase 2: Federated OER Discovery & Context Cache (L3)**: Federated discovery across 71 OER repositories and pedagogical ranking.
3. **Phase 3: Physical OER Download & SHA-256 Forensic Verification**: Real asset download and cryptographic verification (minimum size $>10$ KB, binary validation, rejecting HTML error pages). **If Phase 3 fails, the pipeline halts immediately (*fail-fast*) and blocks all downstream phases at $0.00 cost**.
4. **Phase 4: Pedagogical Deconstruction & Unit Mapping**: Thematic chapter structuring from the physical textbook.
5. **Phase 5: Socratic Interactive Lesson Authoring (A2UI C1/C2)**: Generation of interactive lessons grounded on the canonical blueprints.
6. **Phase 6: Course Pacing Quartet Assembly (L5)**: Assembly of the 4 `CourseSpec` rhythms (`regular`, `intensive`, `exam_mastery`, `remediation`).
7. **Phase 7: Pre-flight Audit & OPS 6-Layer Readiness Radar**: Final readiness audit (`CERTIFIED_GOLD` certification).

#### Idempotent Resumption & Asset Injection Flags

When resolving an issue from a failed phase, the orchestrator detects existing catalog artifacts in `ce-specs` and skips already-completed phases (`[↷ OMITIDO - YA VÁLIDO EN CATÁLOGO]`) in milliseconds, resuming immediately at the required stage:

```bash
# Standard run (halts at Phase 3 if no physical OER can be fetched)
./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2

# Resumption providing a verified local textbook file
./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2 \
  --primary-oer-file=ce-specs/sources/test/unit_1_familias_comunidades_oer_test.pdf

# Injection of an alternative direct URL (timeout configurable via COLABEDU_CURL_TIMEOUT, default 3600s)
COLABEDU_CURL_TIMEOUT=3600 ./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2 \
  --primary-oer-url=https://recursos.educacion.gob.es/fisica_bach2_completo.pdf
```
