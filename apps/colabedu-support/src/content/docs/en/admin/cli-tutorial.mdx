# Operations & Support CLI Tutorial (`ce-cli.sh`)

The `ce-cli.sh` CLI is the unified operational, support, and diagnostic tool for the ColabEdu ecosystem. It allows school administrators, ICT coordinators, and support engineers to manage identities, deploy environments, audit pedagogical standards, and synchronize the institutional knowledge base.

> **Canonical Synchronization**: This tutorial is published synchronously between the **Support KB** and institutional **ColabEdu Docs App**. All changes and newly added options are chronologically audited in [`CHANGELOG_CLI.md`](file:///home/jmolmo/git/colabedu/CHANGELOG_CLI.md).

## 1. Connectivity & Environment Selection

The CLI automatically resolves backend endpoints, tokens, and cluster configurations based on the global `--env` argument:

```bash
# Local development server / on-premise school node (localhost:8081)
./ce-cli.sh --env=local <command>

# Curation / Context Cache server (localhost:8082)
./ce-cli.sh --env=curator <command>

# Institutional environments & remote staging
./ce-cli.sh --env=dev <command>
./ce-cli.sh --env=demo <command>
./ce-cli.sh --env=stage <command>
./ce-cli.sh --env=prod <command>

# Direct connection to a specific institutional tenant
./ce-cli.sh --env=demo-oxford <command>
```

## 9. Federated OER Discovery & Repository Diagnostics (`oer discover`, `oer health`)

### 9.1 Planetary Forensic Discovery & Markdown Table Export (`oer discover`)

Executes semantic discovery and multi-criteria certification (4 vectors) across the federated network of >65 sovereign repositories. Supports exporting forensic reports as structured Markdown tables with direct hyperlinks to resources:

```bash
# Global search for Pythagorean Theorem with hyperlinked Markdown table output
./ce-cli.sh oer discover --subject="GEOMETRY_PYTHAGORAS" --framework="GLOBAL" --format=md

# Direct export to documentation file
./ce-cli.sh oer discover --subject="GEOMETRY_PYTHAGORAS" --framework="GLOBAL" --format=md --output=ce-docs/reports/pythagoras_audit.md
```

| Flag | Default | Description |
|---|---|---|
| `--subject` | (required) | Subject or pedagogical concept to discover (e.g. `GEOMETRY_PYTHAGORAS`) |
| `--framework` | `GLOBAL` | Territorial normative framework (`standard.lomloe.es`, `College Board AP CED`, or `GLOBAL`) |
| `--format` | `summary` | Output format: `summary`, `table` / `md` (Markdown table with links), `json` |
| `--output`, `-o` | (stdout) | Disk file path to save the generated audit report |

### 9.1b Physical Download & SHA-256 Verification (`oer fetch`)

Downloads and physically verifies an OER into `ce-specs/sources/` (HTTP 200 + SHA-256 digest):

```bash
./ce-cli.sh oer fetch --source-url=<url> --subject=<subject> --framework=<framework> [--country=<code>] [--force]
```

### 9.2 OER Repository Diagnostics & Resilience (`oer health`)

Real-time health check, latency monitoring, and SSL certificate verification across the federated network of sovereign OER repositories:

```bash
# Complete health check for all registered catalog connectors
./ce-cli.sh oer health

# Filter by geographic region (America, Europe, or Asia)
./ce-cli.sh oer health --region=europe

# Probe a specific catalog connector
./ce-cli.sh oer health --catalog=no_ndla
```

### `course bootstrap-all` (7-Phase DAG Pipeline with Fail-Fast & Idempotent Resumption)

`./ce-cli.sh course bootstrap-all` orchestrates complete course onboarding through a strict 7-phase Directed Acyclic Graph (DAG) with forensic verification gates (*anti-404 gatekeeper*):

1. **Phase 1: Normative Grounding & C0 Taxonomy**: Competency synthesis and canonical misconceptions catalog verification.
2. **Phase 2: Federated OER Discovery & Context Cache (L3)**: Federated discovery across 71 OER repositories and pedagogical ranking.
3. **Phase 3: Physical OER Download & SHA-256 Forensic Verification**: Real asset download and cryptographic verification (minimum size $>10$ KB, binary validation, rejecting HTML error pages). **If Phase 3 fails, the pipeline halts immediately (*fail-fast*) and blocks all downstream phases at $0.00 cost**.
4. **Phase 4: Pedagogical Deconstruction & Unit Mapping**: Thematic chapter structuring from the physical textbook.
5. **Phase 5: Socratic Interactive Lesson Authoring (A2UI C1/C2)**: Generation of interactive lessons grounded on the canonical blueprints.
6. **Phase 6: Course Pacing Quartet Assembly (L5)**: Assembly of the 4 `CourseSpec` rhythms (`regular`, `intensive`, `exam_mastery`, `remediation`).
7. **Phase 7: Pre-flight Audit & OPS 6-Layer Readiness Radar**: Final readiness audit (`CERTIFIED_GOLD` certification).

#### Idempotent Resumption & Asset Injection Flags

When resolving an issue from a failed phase, the orchestrator detects existing catalog artifacts in `ce-specs` and skips already-completed phases (`[↷ OMITIDO - YA VÁLIDO EN CATÁLOGO]`) in milliseconds, resuming immediately at the required stage:

```bash
# Standard run (halts at Phase 3 if no physical OER can be fetched)
./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2

# Resumption providing a verified local textbook file
./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2 \
  --primary-oer-file=ce-specs/sources/test/unit_1_familias_comunidades_oer_test.pdf

# Injection of an alternative direct URL (timeout configurable via COLABEDU_CURL_TIMEOUT, default 3600s)
COLABEDU_CURL_TIMEOUT=3600 ./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --subject=FISICA --country=es --level=BACHILLERATO_2 \
  --primary-oer-url=https://recursos.educacion.gob.es/fisica_bach2_completo.pdf
```

### `course bootstrap-all --dry-run` (real simulation)

`./ce-cli.sh course bootstrap-all ... --dry-run` and `--dry-run=true|false` are equivalent. In dry-run the backend skips normative synthesis, federated OER discovery and course scaffolding. Always check that the output shows `Dry Run: true`.

```bash
./ce-cli.sh course bootstrap-all --standard=standard.lomloe.es --country=es --level=BACHILLERATO_2 --subject=MATEMATICAS_II --dry-run=true
```

## 12. Billing, Memberships & User Management (`billing`)

The `./ce-cli.sh billing` command enables platform operators to synchronize the canonical pricing manifest (`billing-manifest.yaml`) across Chargebee Dual-Site environments (`colabedu-us` and `colabedu-es`), inspect active tiers, and directly manage user entitlements:

```bash
# Full canonical sync across both Chargebee sites (US & ES)
./ce-cli.sh billing sync --site=ALL

# European site sync only (EUR)
./ce-cli.sh billing sync --site=ES

# List active membership tiers filtered by role or currency
./ce-cli.sh billing list --role=STUDENT --currency=EUR
./ce-cli.sh billing list --role=TEACHER_PRO --currency=USD

# Directly assign a membership tier to a user (e.g. Teacher Ambassador or Practicum intern)
./ce-cli.sh billing assign --user=usr_teacher_123 --tier=pro --role=teacher --reason="Didactics Ambassador UCM"

# Query real-time user entitlements, quota limits, and monthly evaluation usage
./ce-cli.sh billing user --user=usr_teacher_123

# Reset monthly evaluation quota to 0 for a blocked user
./ce-cli.sh billing quota-reset --user=usr_student_456
```

## 17. Optional Zero-PII Gateway & Ephemeral Retention in Grading (`grading evaluate --zero-pii`)

Enables on-demand activation (`--zero-pii=true` or globally via `colabedu.ai.zero-pii-gateway.enabled=true`) of the **Pre-Inference Zero-PII Gateway** during `./ce-cli.sh grading evaluate`, stripping binary metadata (`EXIF/GPS`, `XMP`, `ID3`, `RIFF INFO`) across PDFs, images, and audio files, replacing the student's name with `stu_001` and `<sha256>.<ext>` before calling the LLM, and locally re-hydrating the display name in the final report:

```bash
./ce-cli.sh grading evaluate \
  --path="submissions/Kimberly.pdf" \
  --exercise="ce-specs/catalog/ib/spanish_b/exercises/ib.c2.spanish_b_hl.writing_mock3_paper1.v1.yaml" \
  --level="HL" \
  --anonymity="first-name" \
  --zero-pii=true \
  --llm=true \
```

## 18. OER Visual Slide-PDF Ingestion, Blind Diagrams & Tripartite Course Upgrade (`course import-slides` / `course upgrade --vectors=visual-slides`)

Converts OER/teacher Slide-PDF decks (or extracted OER textbook chapter figures) into 16:9 HD visual slide assets (`1600x900`), generates localized variants (`.en.png`, `.es.png`) and blind assessment diagrams (`.blind.png` with `[ 1 ]`..`[ 4 ]` markers), pairs each slide 1:1 with its SmartBook OER section, and upgrades canonical lessons by replacing dense prose walls with visual slides while preserving a 1-click **📖 Complementary SmartBook Reading** reference (`deepDiveOerRefs`):

```bash
./ce-cli.sh course import-slides \
  --pdf=ce-specs/sources/us/ap/openstax_ap_bio_ch05_slides.pdf \
  --pair-textbook=course.oer.openstax_biology_for_ap_courses.v1 \
  --target-langs=en,es \
  --with-audio-overview

./ce-cli.sh course upgrade \
  --course-ref=course.us.ap_science.hs.BIOLOGY.v1 \
  --unit=2 \
  --vectors=visual-slides \
  --with-audio-overview
```
